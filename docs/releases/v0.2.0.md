## Changes

- Permission rules and live queries support JSON `->` and `->>` extraction, including JSON references matched against user-context lists.
- Optional `latest = { key = ["id"], version = "version" }` rule configuration selects current rows before authorization on every table scan. Moving a record to an inaccessible project retracts its previous visible version.
- Named query parameter inference supports JSON extraction and schema-qualified tables. Validation reports unsupported `$name` placeholders with the query name and supported alternatives (`$1` or `sqlc.arg(name)`).
- Rule compilation errors include rule and table names. Query registration errors include the source file. Configuration failures exit with code 78 before replication or listeners start.

- Updates locked `ctutils`, `rustls`, and `tokio` dependencies to patched versions required by the dependency-policy checks.

## Adoption

Existing rules retain their per-row behavior unless `latest` is configured. Every rule on a versioned table must agree on the setting. Use integer versions and database-enforced non-null, unique `(key, version)` values. Current-row selection also applies to administrative predicates. See [permissions documentation](https://github.com/ThousandBirdsInc/reactive-palimpsest/blob/v0.2.0/docs/PERMISSIONS.md#json-references-and-version-logs) for configuration, tombstones, and historical-query considerations.

`@>`, general scalar subqueries, and rules on database views remain unsupported. Consumers that distinguish process exit codes should recognize 78 as a configuration failure. Kubernetes deployments should run `validate-config` before rollout; an exit code alone does not suppress container restarts.
